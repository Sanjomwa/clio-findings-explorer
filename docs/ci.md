# Continuous integration

One workflow, `.github/workflows/ci.yml`, runs every test suite and check in the repository. It runs on push to `main`, on every pull request and on manual dispatch. It needs **no secrets**: the Postgres service and the compose stack use the local-only placeholder values from `.env.example` (`clio` / `clio-local-only` / `clio_findings`) on a throwaway runner. There is no deploy job in this workflow; deployment is the separate `deploy.yml`, which runs after this one passes on `main` (see [deploy.md](deploy.md)).

Settings: `permissions: contents: read`; one concurrency group per ref with `cancel-in-progress`; a `timeout-minutes` on every job. Actions are pinned to a full commit SHA with the version in a comment. Jobs run in parallel and each sets up its own environment (`astral-sh/setup-uv`, Python 3.12, uv cache on).

## Jobs

| `backend-unit` | `pytest tests/unit` with `pytest-cov` | Logic that needs no database. | `uv run --directory backend pytest tests/unit -v` |

## Things worth knowing

- **Coverage is reported, not enforced.** `backend-unit` and `integration` print a `pytest-cov` table; nothing fails on a threshold.
- **The contract test is the openapi-core response validation.** The backend integration tests validate every response against `openapi.yaml` with `openapi-core`, which satisfies the plan's "Schemathesis, else a hand-written contract test" rule. Schemathesis is deferred to Phase 3 hardening, if time allows.
- **MCP integration tests must not skip.** They skip silently when the database is unreachable, which would look green. The MCP step runs `pytest -v -rs`, tees the output, and fails if it contains `SKIPPED`. (Checked locally: pointing `FINDINGS_DB_URL` at a dead port produces 9 `SKIPPED` lines.)
- **Lint decision (Phase 1d).** Only `backend/` had a ruff config; the other directories were linted with ruff's own, much wider, defaults. A root `ruff.toml` now gives all four directories the backend's selection (`E, F, I, UP, B`), line length 100 and `py312`; `backend/pyproject.toml`'s `[tool.ruff]` is kept (it is now duplicated, and takes precedence for `backend/`). CI pins ruff to 0.17.0, the version in `backend/uv.lock`. `ruff check --fix` (safe fixes only) was applied to `ops/`. The remaining 21 findings were more than 15, so they are per-file ignores in `ruff.toml`, each with a comment: E501 in `agent-hooks/*.py` and `ops/*.py`, B904 in `agent-hooks/spec_first_guard.py` (fail-closed hook), B905 in the two `ops` files that use `zip()`.
- **Workflow lint.** `docker run --rm -v "$PWD":/repo -w /repo rhysd/actionlint:1.7.7 -color`. The first real run on GitHub happens after the first push.
- **Ruff `S` rules (#14).** `S` (flake8-bandit) is on in the root `ruff.toml` and in `backend/pyproject.toml` (which takes precedence for `backend/`). Tests ignore `S101` (assertions). Eleven findings in `ops/` carry a per-line `# noqa: S<code>` with the reason: `subprocess` calls with a list argv and no shell (`S603`, `S607`), the export's SQL built from constant column tuples (`S608`), and the snapshot directory's `0o755` mode (`S103`). Test-only findings in `agent-hooks/tests`, `backend/tests/integration/test_seed.py` and two `ops/tests` files are per-file ignores in the config, each with a comment. No `agent-hooks/` source file has a finding, and none was edited.
- **Injection tests (#14).** `backend/tests/integration/test_api.py` sends seven injection strings (including `' OR 1=1--`, `; DROP TABLE findings;--`, `%27` and 5,000-character strings) to the slug (all four routes), and to the timeline's `country`, `from`, `to` and `state` parameters. Each must return 404 or 422, and the `/api/health` row counts must be the same afterwards. The MCP tests already reject non-`SELECT` and stacked statements (`mcp-server/tests/test_query_snapshot_unit.py`).
- **CodeQL is not in CI yet.** It is the rest of #14 and the issue stays open for it.

## Dependabot

`.github/dependabot.yml` checks weekly, with `open-pull-requests-limit: 3` per ecosystem: `uv` for `/backend` and `/mcp-server`, `npm` for `/frontend`, `github-actions` for `/`, and `docker` for `/backend`, `/frontend` and `/ops/oncall` (the directories with a Dockerfile). The file was checked against the Dependabot schema with `uvx check-jsonschema --builtin-schema vendor.dependabot`. The `postgres` and `grafana/otel-lgtm` images are named only in `docker-compose.yml`, which the `docker` ecosystem does not read, so they are not covered. Major-version updates are ignored (`ignore` on `version-update:semver-major` for every dependency in each of the four entries) and are taken up deliberately by hand, after Dependabot PR #24 (react 18 to 19 without `@types/react-dom`) failed `npm ci` with ERESOLVE.
